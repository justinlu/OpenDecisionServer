# d1-2B 原始文字评估（无 ASR）

用户要求以同样内容直接输入文字，确认 d1 的文本决策准确率。使用 [banking-text-v1](../../datasets/banking-text-v1/README.md)：原128条银行用例＋30条信用卡用例；原始文案、对话历史、标签完整保留，每条语义只计一次。不读录音、不调用ASR、不改写句子。

130核心＝65办理＋65咨询。预测办理才实际调用第二步；65咨询均未被误开功能，65办理均正确进入目标功能。其余28条涉及澄清、取消、转人工或其他，保留在158条完整六分类中，没有强行二分。业务单独诊断使用金标为办理的65条作为样本，不回填实际两阶段成绩。

完整业务识别会给咨询句及边界句也打业务标签，其任务与“只对预测办理句选择业务”的第二步不同。不能把148/158当作核心业务路由的分数，也不能把130/130宣传成完整158条全对。

**菜单并不统一**：完整功能题沿用各原始task（旧集11候选、信用卡6候选）；实际两阶段／平铺诊断沿用此前冻结实验问题（旧集11候选、信用卡16候选）。大类诊断为5类＋unknown，子菜单由模型预测大类生成。合计是两套既定菜单的加总，不是所有158条都做同一16类任务。

## 错例与历史对照

`failures.json` 保存全部14个失败事件（同一语义可能有不同节点，不能叫14条独立用例）。主要错误包括：

- 完整六分类把“查余额”“转账”这种仅报业务名的澄清样本判成办理；一条密码咨询被判转人工。
- 业务标签在只咨询规则、历史指代或转人工／取消场景上有遗漏或混淆；两条信用卡咨询误归还款。
- 分级菜单有一条余额办理在进入账户类后选unknown；平铺业务与真实两阶段均答对。因此文字路径当前没有继续分级的准确率收益证据。

`comparison.json` 对照既有 Omni 原始文字评估与相同核心路由评估。原128条完整意图／业务分数与此前Omni文字结果相同（逐条选择差异见文件）。同一100核心语义，当前d1文字真实路由100/100，此前Omni文字100/100、Omni音频135/200（两声线，67.5%）。说明直接文字决策明显更稳，但同时改变了模型和模态，不能把全部差异归因为单一原因；前一轮官方BF16音频核查另有记录。

## 环境与耗时

纯文本 **d1-2B Q8_0**，不是d1-Omni-2B。`environment.json` 记录实际进程、模型清单、文件校验、硬件及/v1/models；`loaded-libraries.txt` 记录加载库。固定llama.cpp d05706b4f32a545814856e98ca518292585443b9，Metal99层、ctx/batch/ubatch8192、parallel1、4线程，本机Apple M6／16GiB。模型与F16 projector SHA-256均核验匹配清单；请求仅文字，无files。

共706次计分请求，另1次预热，无推理请求错误。316次完整单题、195次实际两阶段请求、195次业务／大类诊断。顺序执行，真实两阶段耗时不含后续诊断。

实际两阶段路由（130条）：p50 **134.7ms**，p95 **253.6ms**，p99 **273.1ms**。包含HTTP及构造请求；一半咨询只做一次调用，一半办理做两次。其他既有服务保持驻留。完整意图单题p50 175.3ms／p95 197.1ms；完整功能单题p50 134.1ms／p95 166.5ms。不同prompt长度、缓存状态与实验接口影响耗时，不能当生产cgo并发性能承诺或与旧实验做速度排名。

## 复核与局限

- `metadata.json`、`specification.json`、实际运行脚本 `measurement.py.txt` 固定实验条件；后续audit强化在仓库脚本中，原测量快照不改。
- `events.jsonl`：每次请求的题目、预期、原始响应、计分、负载哈希和时间；`routes.jsonl`：真实门控与子调用引用；`summary.json`：分组准确率、macro-F1、逐类指标和混淆矩阵。
- `analyze.py` 可离线重建错例及历史对照，审计会重新构造全部请求、核验题目与金标、检查精确事件集合、重算路由和汇总。

```sh
python3 tests/evaluation/banking_text.py audit --output tests/evaluation/results/2026-10-28-d1-banking-text
python3 tests/evaluation/results/2026-10-28-d1-banking-text/analyze.py
```

重跑：按模型清单准备库与权重，启动 `bash scripts/run-liquid-d1.sh d1-2b 18085`，等待 `/health` 返回200；执行 `python3 tests/evaluation/banking_text.py run --output <新目录>`，再复制执行时脚本为该目录measurement.py.txt。默认model=d1-2b，不覆盖旧目录。

这是已经被查看过的合成场景回归集，无训练或题目调优。130条全对不等于线上100%；不涵盖真实输入分布、ASR错误或音频能力，也不能据此单独决定上线。应以未见用例验证并继续覆盖澄清及历史指代。本次只评估，不改变生产统一Go＋cgo单进程目标。
