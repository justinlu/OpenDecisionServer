# Chinese Decision 2B Q8_0 实测：2026-10-27

结论：在这份固定测试上，候选服务准确率明显高于 Julia-1。中文、英文和混合文本改善大，纯拼音仍弱，连写拼音出现退步。模型已下载到 `dist/chinese-decision-2b-q8/`，没有替换服务器默认引擎。

用户要求准确率优先，正式评测使用 Apple M6 Metal GPU，25/25 层 offload。Julia 基线来自先前 CPU ONNX 运行。本报告比较完整服务的准确率，不作同硬件速度结论，也不把提升归因于 GPU。

## 仍需处理的问题

- 纯中文状态组 48/48、纯英文 46/48、中英和四者混用均 48/48，是有限诊断集上的成绩，不能称为通用中文准确率 100%。
- 纯拼音没有解决：带空格 25/48 与 Julia 相同；连写 22/48，低于 Julia 的 26/48。中文＋拼音 47/48，带汉字上下文与整句拼音不能混为一组。
- 数字组 57/72，高于 29/72，但前导零只有 14/24，仍有明显缺口。
- 改善不是逐条单调：custom 修正 169 条、退步 24 条；TokSuite 修正 182 条、退步 54 条。退步清单见 `regressions.jsonl`。外部 `optional_diacritics` 子集从 18/40 降到 14/40，保留这一反例。
- TokSuite 含常识和计算，作者变体可能同时改变题目与选项；不能把所有错误都归因于中文分词。自建仅 36 个语义家族，外部围绕 40 个基础问题，相关变体不能当作 989 个独立真实案例。
- 本候选以 Q8_0 运行，尚未测试 BF16 或 4B；不能推断它们的成绩，也未与官方 PyTorch 路径作同权重对照。

建议：该 2B 候选值得作为中文和中英混用任务的后续接入对象；纯拼音和前导零数字仍需单独改进或兜底。本次不自动切换生产引擎。
