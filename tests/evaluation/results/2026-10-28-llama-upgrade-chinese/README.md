# 新版 llama.cpp 对 Chinese Decision 2B 的兼容性实测

日期：2026-10-28。目标是验证支持 d1 的新版能否作为统一 Go＋cgo、单进程部署的底层库。**不采用 Chinese 原生、d1 HTTP 子进程混用的产品方案。** 本次没有更换在用 SDK 或改动生产引擎。

## 结论

**模型加载、分词、Go/cgo 源码调用和同步原生推理兼容已验证；严格无损迁移门槛未通过。** 新版能正常运行现有 Chinese Decision Q8_0，989 条正确率与旧版相同，性能未观察到退化；但概率存在可重复的差异，一条近并列预测发生变化，不能宣称它是完全等价的动态库替换。

| 检查 | 结果 | 判断 |
|---|---|---|
| 同一 Go/cgo 源码分别用匹配头文件和库编译 | 新旧版均成功 | 源码调用可迁移 |
| 同一 Q8_0 权重及配置 | SHA-256 核验一致，温度 1.074872374534607 | 无权重或校准变更 |
| 1,069 条提示及 A–Z 分词 | 两版均全部匹配冻结 token IDs | 通过 |
| 模型运行 | 两版 25/25 层 Metal，全部原生前向完成 | 通过 |
| 989 条准确率题 | 988/989 个预测一致，正确数相同 | 功能可用，但非逐条完全相同 |
| 24 条生产结构化/长输入 goldens | tokenizer 匹配，均运行完成；最大概率差约 0.000623 | 未过 1e-4 数值门槛 |
| 全部 1,069 条概率 | 最大绝对差 0.0008434699469788143，849 条超过 1e-4 | 未过数值门槛 |
| A/B/A 独立状态清理 | 两版重复 A 的概率差均为 0 | 通过 |
| 旧二进制直接加载新动态库 | C context struct 大小和字段偏移改变 | 不兼容，必须重新编译 |

这里的“源码调用可迁移”只表示同一套已使用的 C API 能按新版头文件重编译运行，不代表 llama.cpp 整个公开 API 都保持 ABI 稳定，也不代表完整 ODS 生产接入已验收。

## 固定数据与准确率

全部 1,069 个原生输入由原有 989 条准确率题、36 个语音助手文字问题、20 条边界输入及 24 条生产 goldens 构成。额外输入没有新的准确率金标准，不混入 504+485 的分母。两版均使用同一份已冻结提示、选项顺序、token IDs、权重和温度。

| 来源 | 旧 SDK 同场运行 | 新 SDK 同场运行 |
|---|---:|---:|
| 自建集 | 435/504（86.31%） | 435/504（86.31%） |
| TokSuite | 366/485（75.46%） | 366/485（75.46%） |

旧版重新运行与冻结的 1,013 条有历史概率参考的输出最大差为 2.22e-16，无预测变化；新版对应参考有 1 条预测变化。35 条复杂输入没有使用验证程序的 Go 字符串 renderer 重建，而是直接使用冻结提示；因此这不是一轮新的 Go 结构化 parser 验收。

## 可重复的数值差异

变化题目是 TokSuite 的 `romanization/312-4.10`：状态为 `liu bian xing de bian shu shi`，选项 A/B/C/D 对应 6/5/7/8，原标签为 A。

| 候选 | 旧版概率 | 新版概率 |
|---|---:|---:|
| C（7） | 0.3038160585 | 0.3038247618 |
| D（8） | 0.3040150582 | 0.3037029420 |

旧版选择 D，新版选择 C，两者都没有选择正确标签 A，因此总准确率相同，但逐条结果并非完全相同。我们没有据此改标签、提示、温度或放宽原先门槛。

对该题、最大概率差题及一个控制题，另起新旧两个进程，各做 10 次交错重复。两版各自的概率都与完整运行完全一致，重复漂移为 0；旧版仍全部选 D，新版仍全部选 C。该复测是事后诊断，不算新的准确率样本。

原始 logits 已有变化，提示/token/温度一致，因此差异已经出现在原生推理输出层，不能仅归因于 Go 的 softmax 或 JSON 渲染。尚未定位到具体 Metal 算子或内核变更；本报告不把它称为已经定位或修复的 bug。

## 同步原生性能

Apple M6、16 GiB、12 逻辑 CPU。新版先测、旧版后测，两个独立程序顺序执行。每模型六个条件，每条件 6 次预热、120 个正式样本，合计 720 个正式观测；这里没有 HTTP、请求排队或实际音频。

下表为 ms、nearest-rank p95，包含内存状态清理、decode、等待 GPU 完成、logits 复制和校准 softmax，不含加载、提示编译和分词。

| 历史对数 | 问数 | 旧 SDK | 新 SDK | 新/旧 |
|---:|---:|---:|---:|---:|
| 0 | 1 | 73.18 | 71.58 | 0.978 |
| 0 | 3 | 225.37 | 214.90 | 0.954 |
| 4 | 1 | 131.82 | 120.68 | 0.915 |
| 4 | 3 | 393.91 | 363.15 | 0.922 |
| 12 | 1 | 212.66 | 197.63 | 0.929 |
| 12 | 3 | 646.31 | 620.37 | 0.960 |

本次新版 p95 约低 2%–8%，没有触发预设的超过10%退化调查项。只有一次顺序扫测，不能认证性能收益或生产 SLA。旧版这次测量比前一天约47ms的短输入参考更慢，不能把跨时段差异算成新版回归；对比以上同场测量为准。没有同时压测 ASR/TTS 或其他模型。

## ABI 与部署边界

用两版各自头文件编译的 `abi.c` 得到：

| 布局 | 旧版 | 新版 |
|---|---:|---:|
| sizeof(llama_context_params) | 160 | 168 |
| offsetof(offload_kqv) | 129 | 137 |
| sizeof(llama_model_params) | 80 | 80 |
| sizeof(llama_batch) | 56 | 56 |

结构体局部大小相同也不能证明整个 ABI 一致；context 的已确认变更足以说明不能把新动态库直接塞给旧头文件编译的 cgo 二进制。现有 ODS 的固定 SDK 哈希保护保持不变，没有伪造 source marker 来绕过它。

下一步统一原生部署需要：使用新版匹配头文件重新编译 cgo/C++ 层；统一管理一次 backend 初始化/关闭与每模型独占 context；将 Chinese 与 d1 的不同提示、多模态处理和读出留在模型适配器内，向 Go 暴露同一套 C ABI。d1 的进程内适配尚未实施，本次验证不能替代其图像/音频一致性验收。

## 门槛、证据与未完成事项

事先规定的迁移门槛是 100% winner 一致、每候选概率差≤1e-4、A/B/A 一致。本次 `strict_upgrade_pass=false`，不是审计脚本报错，也不是通过降低门槛得到的通过。功能与源码调用兼容已经证实；若要求旧版本逐条无损，当前默认构建还不能直接批准迁移。

- `reference.json`、`measurement.go.txt`：实际冻结输入及实测源码。
- `old/`、`new/`：全部 logits、概率、A/B/A 输出、逐次延迟和运行汇总。
- `audit.json`、`differences.jsonl`：独立从 logits 重算概率及各项差异、准确率与p50/p95/p99。Go 的 float32 JSON logits 先恢复 binary32 值，再作 float64 softmax 核验。
- `replay-*`、`replay-reference.json`：事后重复诊断，不改变主评测或迁移阈值。
- `environment.json`、`*-loaded-libraries.txt`：匹配版本的头文件、库、二进制与模型哈希，以及进程实际映射库。
- `abi.c`、`abi-*.json`：结构体 ABI 布局检查。
- [SETUP.md](SETUP.md)：编译、运行和审计命令。

当前生产 SDK 与默认模型没有升级；原有18083服务保持运行，本任务的18084研究体验进程已恢复。旧的混合HTTP接入设计已明确撤回，用户确认的产品方向是 Go＋cgo 单进程。下一阶段应解决或明确接受原生数值差异，再完成统一适配和完整 ODS 取消/关闭、结构化契约及端到端评测；不能因准确率总数相同而省略这些验收。
