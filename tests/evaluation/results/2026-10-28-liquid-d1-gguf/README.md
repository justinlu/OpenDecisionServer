# Liquid d1-2B / d1-Omni-2B：原生 llama.cpp GGUF 实测

日期：2026-10-28。本机 Apple M6、16 GiB、12 个逻辑 CPU；两个新模型使用 Q8_0 主干、F16 多模态编码器及 Metal，依次运行。没有接入 Go 引擎，也没有更改 ODS 默认模型。

结论：两个模型均已在独立 llama.cpp 中跑通。纯文字的 Liquid 候选优先 d1-2B；音频和音频图像组合使用 d1-Omni-2B。已有 Chinese Decision 在自建集上仍领先，而 d1-2B 在 TokSuite 上更好；没有证据支持直接全量替换现有文字模型。多模态正确率目前只是小型合成诊断，不能用于认证真实用户语音的主备方案。

## 固定文字集：正确率

保留原始 504 条业务诊断和 485 条 TokSuite 题目、顺序、标签、选项和提示。noul 以 P(true)>0.5 判定，其余按概率 argmax；即使上游 score 返回中位等级，分类口径也保持不变。

| 模型 | 自建业务集 | TokSuite | 请求错误 |
|---|---:|---:|---:|
| Julia-1（历史） | 290/504（57.54%） | 238/485（49.07%） | 0 |
| Chinese Decision 2B（历史） | 435/504（86.31%） | 366/485（75.46%） | 0 |
| d1-2B | 427/504（84.72%） | 378/485（77.94%） | 0 |
| d1-Omni-2B | 417/504（82.74%） | 370/485（76.29%） | 0 |

这两种来源衡量的内容和分布不同，不用合并百分比选择胜者。历史基线使用相同固定题目，但来自前一天的运行，不是本轮同时重跑。Omni 的初始和最终两次 989 条预测逐条相同；初始运行未保存原始 HTTP 体，正式结果以最终目录为准。

## 原始音频、图片与跨模态诊断

在推理前固定 liquid-d1-media.json：六条中英文合成客服录音及其文本对照、一张上游示例猫图片、两条必须结合图片回答的录音规则、一条口述图片问题，以及静音/纯音。录音状态为 null，音频直接通过 files 送入模型，不发送转录文本，也没有外部 ASR。

Omni 首轮 18 个请求、20 个判断全部正确，无请求错误。d1-2B 的同图三问也全部正确；它不支持音频。

这批录音来自 macOS TTS，每种语言仅一个音色、三个短句；两条跨模态规则分别要求同一猫图片选择红色和蓝色。样本只验证这条原生链路及极小范围行为，不代表真实说话人、口音、噪声、长语音、多图或视频准确率。

重复 20 轮仅用于预热延迟和重复性，共 360 个请求、400 个判断，不能当作 400 个独立准确率样本。

## 环境、资源与实现边界

- llama.cpp 源码固定为 d05706b4f32a545814856e98ca518292585443b9；官方 GGUF 四个文件的字节数与 SHA-256 全部核验。版本、构建信息、权重哈希、二进制哈希、CPU/系统版本和参数见 environment.json、download-verification.json、gguf-decision-metadata.json。
- 完整加载核验另见 d1-gpu-load.log 与 omni-gpu-load.log，两者均为 25/25 层 GPU 卸载。验证在性能计时结束后另行进行，使用相同权重和推理参数、较详细日志。
- 使用模型自带的校准温度：d1-2B 约 1.3374，Omni 约 3.3830；没有使用测试结果调温度、提示或标签。上游校准不保证在本业务分布上仍校准。
- 一次加载一个新模型；保留了已有 18083 端口的 ods-metal 服务，但没有对它同时压测。本轮没有并行 ASR/TTS 或开放到达率负载。
- 两次 Omni 和一次 d1 的完整文字运行均为零错误，报告中的比较以最终含原始响应的两组为准。
- 图片、音频及语言模型的容量不等同于本服务已支持的接口。当前原生决策接口未覆盖视频、抽取、框选、数值估计和多选等完整新题型；普通 props 的 modality 标志也不能证明决策端点已支持视频。

- d1-Omni-2B 整个进程生存期最大 RSS：2.401 GiB（/usr/bin/time -l）；每秒采样见 omni-resources.jsonl。RSS 不是 GPU 总显存或统一内存的完整占用。
- d1-2B 整个进程生存期最大 RSS：2.284 GiB（/usr/bin/time -l）；每秒采样见 d1-resources.jsonl。RSS 不是 GPU 总显存或统一内存的完整占用。

## 主备选择建议

1. Liquid 的文字路径优先评估 d1-2B：这轮两个固定集均高于 Omni，无须为纯文字额外选择 Omni。
2. 音频图文路径单独使用 d1-Omni-2B 候选；短录音单问值得继续验证，但图文音频组合和长历史、多问、并发路径目前不能承诺 100 ms。
3. 保留既有 Chinese Decision 作为文字对照和备用候选。它在自建集的 noul/score 与部分混合输入上仍有优势，而 d1-2B 在 TokSuite、正常中英文本和部分数字形式上较好。需要按实际业务流量及错误成本选择，不能只按合并分数切换。新 d1 的 confidence 返回所选答案概率，与现有服务的归一化 confidence 公式不同，备用触发阈值也需重新验证。
4. 本次不改默认模型。确定主备前，应增加真实脱敏语音、真实截图、否定改口和数字业务录音，并用独立样本验证置信度阈值、长上下文及 GPU 争用。

## 核验与复现

[SETUP.md](SETUP.md) 给出下载、构建、启动和完整评测命令。`python3 tests/evaluation/audit_liquid_d1.py` 从原始响应重算两个模型的 1,978 条准确率、2,880 条延迟观测及 379 个媒体诊断请求（其中 360 个为重复观测）。分来源配对的修正/退步数、全部细分指标和资源采样峰值见 comparison.json。原始 fixture 的哈希和录音时长见 media-manifest.json。

自建仅 36 个独立语义家族，TokSuite 围绕 40 个基础问题；变体之间相关，不能把 989 行当成 989 个独立真实用户案例。没有证明公共测试集未进入预训练，也没有跨日多次重复或实际生产流量验证。
