# 新版 llama.cpp 的 Chinese Decision 兼容性验证

用户要求先确认支持 d1 的新版能否兼容现有 Chinese Decision，并已明确选择统一 Go＋cgo、单进程部署，不接受不同接入方式混用。本轮验证不实施新的 Go backend，不修改生产 SDK 的哈希保护，不替换在用动态库。

## 固定条件

- 旧 SDK：现有固定 llama-cpp-python 0.3.36 所带源码，归档 SHA-256 `832db0699007f1be95a7e41ef12e88926b02ba836461e36a36372db2760c1a2e`。
- 新 SDK：d1 实测使用的 llama.cpp 提交 `d05706b4f32a545814856e98ca518292585443b9`。
- 同一份 Chinese Decision 2B Q8_0、提示和 tokenizer；温度固定 `1.074872374534607`。
- 同一份 Go/cgo 验证源码分别按各版本头文件重新编译，两个程序顺序运行，绝不在一个测试进程中加载两版 Metal 库。
- 使用现有 1,045 条冻结输入，再加入 24 条生产 goldens（结构化、26 候选和超过512 token的分块输入），共1,069条；原准确率集仍是504+485，不新增或调整标签。
- context=16384、seq=1、batch=512、ubatch=512、4线程、全层 Metal、flash attention disabled。每个作业前清理完整 hybrid memory。
- 先声明迁移门槛：100% winner 一致，每候选概率绝对差≤1e-4，A/B/A状态重置一致；不通过时如实报告，不调温度或提示掩盖差异。
- 性能使用固定18个语音助手文字模板，6次预热，每历史/问数组合120次；比较同步原生完成时间，不当作HTTP或生产SLA。性能变化超过10%列为需调查项，不改变数值一致性门槛。
- 测量期间暂时停止本任务此前启动的18084 Omni体验进程，测试后恢复；保留18083原有Chinese服务。

- [x] 验证头文件/C API编译及工件身份。
- [x] 运行新旧两个串行原生程序，保存token检查、候选logits、概率、A/B/A与延迟。
- [x] 独立重算准确率、逐条差异、边界golden与延迟，区分模型/源码兼容和旧二进制ABI兼容。
- [x] 记录结论及统一接入后续边界，审查并将结果推送main。

验证结果：加载、源码调用与token一致性通过；相同准确率，1条近并列答案变化，最大概率差0.00084347，严格迁移门槛未通过。该结论不通过调整阈值改成通过。
